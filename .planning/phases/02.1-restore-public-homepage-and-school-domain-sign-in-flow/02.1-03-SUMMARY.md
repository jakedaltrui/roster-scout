# Phase 02.1 Plan 03 Summary

Every authenticated homepage workbook request now also creates or reuses the school organization’s durable saved report without disrupting the immediate Excel download.

## Accomplishments

- Promoted exact catalog resolution to a shared route boundary and revalidated team, season-team, division, display name, and team ID.
- Accepted the canonical report/job/usage/audit graph before external collection, using the download event UUID as the idempotency key.
- Best-effort dispatched the durable job and returned a same-origin `X-Roster-Scout-Report-URL` header while retaining the original workbook response.
- Simplified portal navigation to New report, Saved reports, and Account; removed membership management and organization switching from primary navigation.
- Kept report history, explicit refresh, exact historical download, and protected direct administration routes intact.

## Verification

- Homepage acceptance, replay convergence, rollback-before-collection, CSRF, report library, Phase 2 release, and tenant-isolation tests pass.
- Python compilation and `git diff --check` pass.

## Decisions

- The homepage remains the only promoted report selector; `/reports/new` is retained as a protected compatibility/fallback route but is absent from navigation.
- Durable acceptance commits before external collection, so an upstream workbook failure cannot erase the saved request or its audit trail.
- Portal account details show the school and verified email, while administrative routes remain hidden from the core flow.

Not deployed. Production remains unchanged pending user approval after all Phase 02.1 verification.
