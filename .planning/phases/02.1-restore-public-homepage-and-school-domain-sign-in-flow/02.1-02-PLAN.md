# Plan 02.1-02: Public Homepage and Automatic Sign-In Resume

## Objective

Restore the original homepage as the primary product interface and insert authentication only at the validated generation boundary.

## Tasks

1. Add browser and route tests proving public homepage/catalog/logo access, authenticated `/scrape`, exact allowlisted callback return, signed-in header state, no duplicate resume, and safe storage fallback.
2. Make `/` public for every session, add minimal Sign in/Saved reports affordances, contextualize the hosted sign-in handoff, and add the bounded resume state machine with CSRF on authenticated generation.
3. Update inaccurate homepage copy without changing the established visual hierarchy; run focused Python/Node tests and diff hygiene.

## Threat Model

- The resume URL is exact and allowlisted.
- Stored state excludes email, account, organization, tokens, workbook data, and arbitrary destinations.
- Server catalog identity is revalidated after sign-in.
- Authentication remains mandatory before `/scrape` performs collection.
