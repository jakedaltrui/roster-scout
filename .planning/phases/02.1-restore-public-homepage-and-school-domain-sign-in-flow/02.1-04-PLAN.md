# Plan 02.1-04: Corrective Release, Security, and Visual Verification

## Objective

Prove the revised Phase 2 customer journey without weakening the secure backend or touching production.

## Tasks

1. Add a deterministic end-to-end story and release validator covering domain joins, sign-in resume, saved report acceptance, workbook delivery, tracking, tenant denial, migration lifecycle, catalog, and existing regressions.
2. Render the pre-Phase-2 baseline and corrected homepage at desktop/mobile sizes, compare layout and interaction hierarchy, and record the UI review.
3. Re-audit the changed domain trust model, run deep code/security/regression checks, close every finding, and write final verification with production launch still false.

## Threat Model

- Domain membership is an explicit reviewed authorization boundary, not a convenience hint.
- The release gate must include negative lookalike/subdomain/transfer cases.
- No live provider, production database, deployment, billing, or customer data is contacted.
