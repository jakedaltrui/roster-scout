# Plan 02.1-03: Saved Report Acceptance and Minimal Portal

## Objective

Make the familiar homepage download produce the durable saved-report record and simplify the portal around the few actions customers actually need.

## Tasks

1. Add acceptance/rollback/idempotency tests for the homepage route and a full signed-in download-to-portal story.
2. Reuse the canonical report acceptance and dispatch boundaries before compatibility workbook collection; return a safe report URL header without changing workbook bytes or acknowledgement tracking.
3. Remove the second team-selector experience from primary portal navigation, simplify empty/detail affordances, hide organization administration, and rerun tenant isolation and historical-download tests.

## Threat Model

- Durable report acceptance must commit before external collection.
- Organization scope comes only from the revalidated session membership.
- Validation or persistence failure returns no workbook and creates no partial usage/audit graph.
- Historical snapshots and artifact proofs retain exact tenant scope.
