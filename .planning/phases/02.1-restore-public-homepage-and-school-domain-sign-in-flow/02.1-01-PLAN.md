# Plan 02.1-01: Verified Institutional Domain Membership

## Objective

Replace the Phase 2 no-domain-auto-join rule with a narrow, auditable `.edu` organization resolver while preserving explicit invitations and cross-tenant isolation.

## Tasks

1. Add failing PostgreSQL tests for canonical root parsing, subdomain convergence, exact alias override, spoofed/non-`.edu` rejection, concurrent first join, provider-email change, membership provenance, and reversible migration lifecycle.
2. Add revision 0022, `OrganizationDomain`, membership provenance, fixed audit reasons, and the transaction-scoped resolver. Integrate it after verified identity linking and prefer its organization for the resumed homepage flow.
3. Run focused identity/organization/migration tests, cross-organization denial tests, drift checks, and diff hygiene.

## Threat Model

- Provider verification is mandatory; request email/domain fields are never accepted.
- Root calculation is strict and fail-closed.
- PostgreSQL advisory locking serializes absent-domain creation.
- Email-domain changes cannot retain stale domain-derived access.
