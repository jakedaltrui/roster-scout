## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Fetch response -> browser state | Only a matching successful workbook receipt may advance toward acknowledgement. |
| sessionStorage -> acknowledgement API | Stored UUID/proof state is untrusted, short-lived idempotency state and never identity. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-35-01 | Spoofing | echoed receipt header | mitigate | Require exact equality with the active UUID before marking download initiated. |
| T-01-35-02 | Repudiation | ambiguous retries | mitigate | Explicit persisted state transitions retain the same UUID until definitive completion/failure. |
| T-01-35-03 | Information Disclosure | browser storage | mitigate | Store only expiring opaque UUID/proof/state/timestamp in sessionStorage; no identity or report data. |
| T-01-35-04 | Tampering | client acknowledgement order | mitigate | Executable JS tests assert blob read and anchor initiation precede ack. |
| T-01-35-05 | Denial of Service | stuck pending ack | mitigate | 15-minute expiry and bounded one-attempt storage prevent indefinite accumulation. |
</threat_model>
