## Phase Goal

**As a** Roster Scout operator, **I want to** publish existing NCAA D1/D2/D3 results through a durable job into an immutable, provenance-rich canonical snapshot, **so that** every downstream report can rely on one auditable source of truth without breaking today's workbook workflow.

<objective>
Separate workbook preparation from successful-download acknowledgement and enforce an idempotent, same-origin server receipt contract.

Purpose: A server response is not a successful download; only the browser that read the blob and initiated the download may acknowledge it.
Output: Prepared response headers, protected acknowledgement route, best-effort native persistence behavior, and route regressions.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> acknowledgement API | Cross-origin and replayed input attempts to create a successful-download event. |
| Signed prepared-workbook proof -> PostgreSQL | An opaque UUID/proof pair attests only recent workbook preparation, never user identity. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-34-01 | Spoofing | `/api/downloads/ack` | mitigate | Exact Origin/host and Fetch-Site checks plus a 15-minute signed UUID proof. |
| T-01-34-02 | Tampering | acknowledgement payload | mitigate | Exact JSON shape, canonical UUID parsing, and no client-supplied actor/org. |
| T-01-34-03 | Repudiation | ambiguous ack retry | mitigate | Database uniqueness on event type/key and replayable same-UUID proof make retries idempotent. |
| T-01-34-04 | Denial of Service | proof validation | mitigate | Exact 15-minute maximum age, 1-KiB body/512-character token bounds, and no server-side receipt collection. |
| T-01-34-05 | Information Disclosure | receipt/logging | mitigate | UUID is nonidentity; no PII/fingerprint storage and no secret, proof, or raw payload logging. |
| T-01-34-06 | Spoofing | cross-worker proof signing | mitigate | Fly or WEB_CONCURRENCY&gt;1 startup requires the same decoded-32-byte-or-longer shared secret; clean-process interoperability and missing/short-secret tests enforce it. |
</threat_model>
